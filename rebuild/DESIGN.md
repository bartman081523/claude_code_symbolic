# 2-Stage Epistemic Thinking for claude-code — Design

**Status: in-source patch (v1, verified live).** The 2-stage thinking lives
**inside** the claude-code binary itself, at the request chokepoints, applied
as a JS-source patch via `gen_patch.py` + `patch.py`. The earlier external-proxy
design (`two_stage_shim.py`, now **obsolete/deprecated**) is retained only as a
reference; do not use it.

## Goal

**Opus = decider (stage 1, cheap/short thinking), Sonnet = judge (stage 2,
heavy thinking, cheaper per token)** — applied through claude-code's *normal*
thinking flow, **not** as a hermes plugin and **not** via an external proxy.
Moves the expensive long thinking off Opus onto Sonnet.

## Reference patch (hermes)

`hermes-agent` commit `1a7bb2983` — SciMind 5.0 epistemic mandates + a
worker-decoder *post-hoc output transform plugin*. We do **not** copy the
plugin shape; we reuse only the **epistemic mandates** (`SCIMIND_5_0_PREAMBLE`
in `scimind_mandates.py`, ported verbatim) as the **judge's** system preamble.

## How claude-code does thinking (evidence from the bundle)

- **Single main model.** `getMainLoopModel` (266 refs) is the main-loop model;
  no separate "thinking model" — extended thinking runs on that same model.
- **Thinking request shape.** `thinking:{type:"adaptive",display:"omitted"}`
  in `-p` mode by default (NOT `type:"enabled"`); `ultrathink` raises the
  budget. The trigger accepts both `enabled` and `adaptive`.
- **Tier system.** Env overrides `OPUS_MODEL` / `SONNET_MODEL` / `HAIKU_MODEL`
  / `SUBAGENT_MODEL`; `ANTHROPIC_BASE_URL` redirects the API endpoint.
- **Request paths (verified by instrumentation).** claude-code calls
  `client.beta.messages.create({...body, stream:true}, opts).withResponse()`
  for **every** turn (both `-p` one-shot and the interactive loop), then
  destructures `let {response, data} = await ...withResponse()` and iterates
  `data` with `for await`.  `client.beta.messages` is the **BASE** `Messages`
  class (`$Je`, posts `/v1/messages?beta=true`), NOT `BetaMessages`/`A7`.
  `Messages.stream()` → `MessageStream._createMessage` is **not** used by
  claude-code.

## The in-source patch (where the hooks go)

Five JS-source edits to module #0 (`cli.js`), generated by `gen_patch.py` into
`patches.json` and applied by `patch.py`:

1. **Helper insert** — at the IIFE opener, declare `__twoStage`,
   `__tsTrigger`, `__tsTierModel`, the `__tsInStage1` boolean recursion guard,
   `__tsDbg`/`__tsLog` (gated by `TWO_STAGE_DEBUG`) and the inlined
   `__SCIMIND_PREAMBLE__`. Both hooks call these.

2-3. **Hook A — `Messages.create` (base `$Je` + beta `A7`)** — the **real main
   turn**.  `create(e,t)` does `let r=Hal(e), {betas:n,...o}=r; ...; return
   this._client.post("/v1/messages?beta=true",{body:o,...,stream:r.stream??!1})`.
   The replacement prepends a trigger check on `o`:
   - **stream + triggered** (`r.stream` true): returns a **lazy proxy**
     `{withResponse(){ return (async()=>{ b=await __twoStage(this,o);
     b.stream=true; __tsInStage1=true; p=this.create(b,t);
     return await p.withResponse(); })() }}`.  The caller calls
     `.withResponse()` synchronously (the contract claude-code uses); the async
     body first awaits stage 1, then **re-enters `this.create(judgeBody)`**
     under the `__tsInStage1` guard (so the re-entered `create` skips the
     trigger and does the original post — yielding the real SDK `APIPromise`),
     and delegates `.withResponse()` to it.  The SDK `APIPromise.withResponse()`
     returns `{data, response, request_id}` where `data` is the `v7` SSE
     `Stream`; the caller iterates that unchanged — **real stage-2 SSE flows
     through with zero synthesis**.  NOTE: do **not** `await` the `APIPromise`
     before calling `.withResponse()` — awaiting it resolves to the `v7`
     Stream which lacks `.withResponse()`.
   - **non-stream + triggered**: an async IIFE awaits stage 1, sets
     `b.stream=false`, and returns `this.create(b,t)` (the stage-2 Promise).
   - **non-triggered**: the original `this._client.post(...)` runs unchanged.

4-5. **Hook B — `MessageStream._createMessage` (base `uLr` + beta `TLr`)** — the
   `.stream()` path (a safety net; claude-code does not currently use it).
   Before the existing `await e.create({...t,stream:!0}).withResponse()`, if
   `__tsTrigger(t)` it runs stage 1 and rewrites `t` to the judge body; the
   existing `e.create` then becomes stage 2.

A thinking turn is identified by `body.thinking?.type` being `"enabled"` or
`"adaptive"`.  Stage 1 runs a non-stream `create` with a small budget on the
decider model, guarded by `__tsInStage1` so stage 1's own `create` (and the
stage-2 re-entry) cannot re-trigger.  On stage-1 failure the helper falls back
to the original body (no crash, no 2-stage that turn).

### Shared helper contract

`async __twoStage(client, body)` does the stage-1 round trip and **returns the
judge body** (not the response): `messages = body.messages + [{role:"user",
content: JUDGE_INSTRUCTION + draft}]`, `model = stage2 tier model`,
`thinking = {type:"enabled", budget_tokens:JUDGE_BUDGET}`,
`system = SCIMIND_PREAMBLE + body.system`, `tools = body.tools` (so the judge
emits authoritative tool calls).  The caller issues the real stage-2 request —
so streaming, auth headers, signal, and SDK response shaping all stay intact.

### Config (env), tier-based

| var | default | meaning |
|---|---|---|
| `TWO_STAGE_ENABLED` | `1` | master switch |
| `TWO_STAGE_STAGE1_TIER` | `opus` | decider tier → `OPUS_MODEL`/`SONNET_MODEL`/`HAIKU_MODEL` |
| `TWO_STAGE_STAGE2_TIER` | `sonnet` | judge tier → ditto |
| `TWO_STAGE_DECIDER_BUDGET` | `2000` | stage-1 thinking budget |
| `TWO_STAGE_JUDGE_BUDGET` | `16000` | stage-2 thinking budget |
| `TWO_STAGE_DECIDER_CONCISE` | `1` | if on, tell the decider to produce a SHORT draft (key approach + tentative answer only); the judge writes the full response. Drives the opus-tier token saving. |
| `TWO_STAGE_TRIGGER_MODELS` | (any) | optional comma-sep allow-list of incoming model names |
| `TWO_STAGE_DEBUG` | unset | if set (and not `0`/`false`/`no`/`off`), append a per-call trace to `/tmp/ts.log` |

If a tier env var is unset, that stage falls back to the incoming `body.model`.

## How the patch is applied (source, not bytecode)

`patch.py` patches the JS **source** of module #0 inside the `.bun` section.
Same-length patches write in place.  This patch **grows** the source (+6155
bytes: helper + hook edits), so `patch.py` uses the **repoint** path: it writes
the longer source into the module's stale **bytecode region** (payload offset
120, 152 MB — plenty of room), repoints the module-table `contents`
StringPointer to `(120, new_len)`, and nulls the `bytecode` StringPointer to
`(0,0)`.  Bun then parses the source and skips the now-empty bytecode.  The
module-table entry is located by searching for the unique `contents`
StringPointer — version-agnostic.  This reuses the bytecode region as storage;
it does **not** edit bytecode.

## Build & run

```bash
cd rebuild
python3 gen_patch.py        # regenerate patches.json
python3 patch.py claude.orig out/claude.patched patches.json   # apply
./out/claude.patched --version                               # boots -> 2.1.214

# Smoke test against Ollama Cloud (glm-5.2 decider / minimax-m3 judge):
ANTHROPIC_BASE_URL=http://127.0.0.1:11499 ./run-2stage.sh -p 'ultrathink: 2+2?'
# passthrough (stock behavior):
TWO_STAGE_ENABLED=0 ./run-2stage.sh -p '...'
# custom tiers / budgets:
TWO_STAGE_STAGE1_TIER=sonnet TWO_STAGE_STAGE2_TIER=haiku \
  TWO_STAGE_DECIDER_BUDGET=1500 TWO_STAGE_JUDGE_BUDGET=12000 ./run-2stage.sh
```

`run-2stage.sh` mirrors the `cc ollama` launcher env (base URL, auth token, tier
models) and adds the `TWO_STAGE_*` config (stage1=opus tier→`OPUS_MODEL`,
stage2=sonnet tier→`SONNET_MODEL`).  Point `ANTHROPIC_BASE_URL` at
`log_relay.py` (127.0.0.1:11499) to see exactly what goes on the wire.

## Verification (done — live, against Ollama Cloud)

- `out/claude.patched --version` → `2.1.214 (Claude Code)` (boots; Bun
  source-fallback confirmed).
- **End-to-end 2-stage turn** (`OPUS_MODEL=glm-5.2:cloud
  SONNET_MODEL=minimax-m3:cloud`, `ultrathink: What is 2+2?`): exit 0, answer
  "Four.".  `TWO_STAGE_DEBUG=1` trace shows stage1 = `glm-5.2:cloud` non-stream
  budget 2000, stage2 = `minimax-m3:cloud` stream budget 16000.  `log_relay.py`
  confirms on the wire: probe (minimax, no thinking) → stage1 (glm, non-stream,
  thinking 2000, tools=27, msgs=2) → stage2 (minimax, stream, thinking 16000,
  tools=27 preserved, msgs=3 = original 2 + judge instruction).
- **`TWO_STAGE_DEBUG=0`**: 2-stage still works, no `/tmp/ts.log` written (clean).
- **`TWO_STAGE_ENABLED=0`**: stock passthrough — single request, no stage split,
  answer correct ("Ten.").
- Non-"ultrathink" `-p` turn: claude-code sends `adaptive` thinking by default,
  so 2-stage fires per the "all thinking turns" design (answer "Hi").
- Node harness (8 logic tests, all PASS): trigger gating, stage1 body, judge
  body (SciMind preamble, tools preserved, draft as final user turn),
  `__tsInStage1` recursion guard, tier config, stage-1-failure fallback.

## Cost check (live, via `usage_relay.py`)

Same hard reasoning task (4-seat constraint puzzle), stock vs 2-stage, token
usage captured by relaying through `usage_relay.py` (127.0.0.1:11500), which
parses `usage` from non-stream JSON and stream SSE (`message_delta.usage`):

| config | opus-tier (glm) output | sonnet-tier (minimax) output | answer |
|---|---|---|---|
| **stock** (single glm, adaptive) | **717** | — (housekeeping only) | 2 ✓ |
| 2-stage, decider budget 2000, verbose draft | 828 | 1766 | 2 ✓ |
| 2-stage, decider budget 400, verbose draft | 749 | 1878 | 2 ✓ |
| **2-stage, decider budget 1000, CONCISE draft** | **157** | 1131 | 2 ✓ |

Findings (honest):

- A **verbose decider** (draft follows the task's "show full reasoning") does
  NOT reduce opus-tier tokens — the decider's draft text is comparable to
  stock's answer text, so glm output stays ~750-830 vs stock 717.  The 2-stage
  value there is purely *epistemic* (the judge independently verifies the draft
  — on the puzzle it brute-forced all 24 permutations to falsify the draft).
- A **concise decider** (`TWO_STAGE_DECIDER_CONCISE=1`, the default) tells the
  decider to emit only the key approach + a tentative answer, and the judge
  writes the full response.  This drops opus-tier output from **717 → 157
  (−78%)** while the heavy thinking+writing (1131) moves to the cheaper
  sonnet tier.  This is the configuration that realises the user's goal
  ("move expensive thinking off Opus onto Sonnet").
- The saving is task-dependent: it is largest when the stock model would
  otherwise think/write heavily on the expensive tier.  For trivial tasks
  where adaptive thinking stays tiny, 2-stage adds a decider round-trip
  (extra latency + a small cheap-tier judge call) with little token saving.

Note: here both tiers are free Ollama Cloud models, so "cost" is abstract —
the numbers prove the *routing architecture* (heavy thinking on the sonnet
tier at a controlled budget, cheap concise draft on the opus tier), which is
what matters for a real paid deployment.

### Tool-use loop (live, verified)

Forced a tool call via a scoped `--allowedTools Read` grant: "read
/tmp/2stage_tooltest/marker.txt and report its contents".  The trace shows
**two full 2-stage rounds** — round 1 judge emits a `Read` `tool_use` (real SSE
block forwarded through the proxy), claude-code executes it, feeds the
`tool_result` back; round 2 judge emits the final answer ("hello-2stage",
correct).  Streaming survives end-to-end across both rounds.

## Relationship to the obsolete proxy

`two_stage_shim.py` (v0.1) implemented the same 2-stage split as an external
proxy on `ANTHROPIC_BASE_URL`.  It is **deprecated** — the in-source patch
above supersedes it (no extra hop, real SSE streaming instead of synthesis, no
signature concerns).  Kept in-tree as a reference only.
